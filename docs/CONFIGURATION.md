# 配置、数据与 GitHub 边界

入口：[README](../README.md)。规则：代码和加载逻辑留在 Git，实际值、凭据与运行数据留在外部。公开域名、变量名、构建配置不是凭据。

## 仓库内

| 文件/目录 | 含义 |
| --- | --- |
| `src/site.config.ts`、`astro.config.mjs`、`tsconfig.json` | 公开站点信息与项目构建配置 |
| 根 `package.json`、`package-lock.json` | 网站和判题服务的开发入口、锁定的 Node 依赖 |
| 源码中的环境变量读取、默认值和接口 | 程序逻辑；实际值由外部配置提供 |

## VPS 权威数据与配置

| 位置 | 内容 |
| --- | --- |
| `/etc/hhikr-web/env` | 网站启动环境与生产凭据 |
| `/srv/hhikr/data/` | 网站数据库、上传与生产内容 |
| `/etc/hot100/env`、`/var/lib/hot100` | 判题服务环境与运行数据 |
| `/etc/caddy/` | HTTPS 与反向代理 |

## 已提交 / 未提交

提交：项目源码、既有接口、配置加载器、公开构建配置、依赖锁、许可证、测试与项目文档。

不提交：数据库/上传、登录/token、密钥/密码/证书私钥、依赖目录、发布包与运行日志。

`.deployment/`、`tools/deploy/`、`.data/`、`node_modules/` 和生成目录均由 Git 忽略。最终以 `git ls-files` 和实际提交清单核对。

## 查询与修改顺序

1. 明确需要源码还是生产记录，先选机器。
2. 定位文件/环境变量；必要时只读字段或元数据，不输出秘密值。
3. 修改源码用测试数据；发布前再次比较最新运行文件和依赖。
4. 把具体配置变更、服务影响、恢复办法提交用户确认，再写入生产配置。
